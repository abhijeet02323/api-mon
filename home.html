A practical reliability toolkit

From a single health check to a service signal you can act on.

Bring together endpoint availability, API behavior, and incident investigation without losing the evidence behind each status.

◉

Availability and latency

Check public HTTP endpoints against one or more accepted status codes. Set request timeouts and latency thresholds, then inspect recent outcomes and response-time history.

◷

Schedules that fit the service

Run checks on an interval, once each day in a selected timezone, at a one-time date and time, or turn scheduled checks off while keeping manual checks available.

△

Incidents with evidence

Consecutive availability failures create a deduplicated incident with the observed status, expected codes, latency, endpoint, and available error details. Recovery updates the incident lifecycle.

⇢

Scenario-based API tests

Build chained HTTP workflows with JSON assertions and extracted values. Review per-step outcomes, response codes, timings, and validation failures in one history.

✳

AI Assist with monitor context

Ask follow-up questions using a monitor's recent checks and optional incident facts. Saved conversations are kept per monitor, and incident summaries can be generated on demand.

▥

Metrics for Grafana

Prometheus scrapes aggregate service metrics and the latest response-time gauge for each monitor. The provisioned Grafana dashboard charts latency and operational counts.

A clear path from signal to action

Understand what happened, then choose the next step.

SentinelAPI keeps checks, scenario results, and incident state close together so investigation starts with concrete observations.

STEP 01

Define the signal

Add a public HTTP(S) endpoint, select expected status codes, set timeout and latency limits, and choose a schedule that matches its role.

STEP 02

Validate real behavior

Use a monitor check for availability or add a scenario to validate response fields, chain requests, and see which individual step failed.

STEP 03

Investigate with context

Review incident details and recent history, acknowledge or resolve the issue, and ask AI Assist to explain the supplied evidence.

Designed for controlled checks

Useful diagnostics, with deliberate boundaries.

Monitoring should be predictable for both your service and the systems it calls. SentinelAPI keeps outbound requests bounded and makes state-changing scenarios explicit.

  • Only public HTTP(S) targets are accepted; local and private destinations are rejected.
  • Redirects are disabled and request timeouts are bounded.
  • Scenario write methods require confirmation and a separate scheduled-write opt-in.
  • Scenario response bodies are bounded and are not persisted.
